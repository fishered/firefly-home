# Firefly v1.2.1

发布日期：2026-11-07

v1.2.1 在 1.2.0 多租户治理基础上补齐配额预演与容量规划闭环。运维人员可以在修改配额前查看当前用量、历史峰值、触顶与拒绝证据，逐维度采用确定性建议，再通过原有版本 CAS 安全应用。

## 本次交付

- `POST /api/tenants/{tenantId}/quota-preview` 只读取 policy、usage 和容量样本，不创建 reservation，不修改 Outbox、审计或租户版本。
- 并发、CPU、内存、backlog 和触发速率均提供当前值、平均值、峰值、触顶比例、拒绝数、建议值和稳定原因码。
- 推荐固定使用 `ceil(max(current, peak) * (1 + headroom))`。数据覆盖不足、被现配额截断或跨 policy/runtime 版本时，不输出伪精确下调建议。
- Admin UI 支持预览、逐项采用推荐、关键风险二次确认，以及使用同一 `expectedVersion` 应用。并发修改会返回 `409 tenant_version_conflict`。
- 全租户容量报告按风险排序，支持有界 JSON/CSV 导出；列表单页最多 500，导出最多 1,000 个租户和 2 MiB。
- v21 additive feature migration 新增容量样本和 flush 去重表。准入热路径仅写有界内存缓冲，数据库异常或背压不会阻塞准入、派发和终态事务。

## 兼容性与升级

本版本保持 Executor v1/v2、Plugin API level 1、任务定义、公平队列和核心数据库 schema 版本 12 不变。1.2.0 节点可以与 1.2.1 滚动共存；混合版本窗口会标记为 `MIXED_VERSION`，不会生成不可靠的下调建议。

升级前备份数据库并安装对应方言的 v21 migration。回滚到 1.2.0 时停止 sampler 即可，新增表可以保留。完整操作见[配额与容量规划](../features/capacity-planning.md)。
