# Firefly v1.1.5

发布日期：2026-09-30

v1.1.5 完成了补数与执行重放的生产化闭环。这个版本把 1.1.3/1.1.4 已有的公共模型、任务快照和失败目标语义接入 JDBC、Admin HTTP 与独立管理控制台，让运维人员可以安全预览、分批放量、恢复和重放历史执行。

## 本次交付

- Backfill 操作、触发点、游标、Canary 状态和下次可派发时间现在持久化到 JDBC。H2、MySQL 和 PostgreSQL 都通过 v18 feature migration 增量创建补数表。
- 多个 API 节点通过租约和 fencing token 竞争补数操作；节点退出或重启后，新 worker 从持久化游标继续，已创建的 execution 不会被重复派发。
- Admin API 提供补数预览、创建、列表、详情、暂停、继续、取消和 Canary 全量放开，并保留批次大小、每秒限速和最大执行数边界。
- Admin UI 新增“补数管理”页，可在提交前查看触发点数量、预计时长和 Canary 规模，并跟踪已派发、失败与剩余进度。
- 执行重放从原 Outbox 读取不可变任务快照，与当前定义比较参数、日历和依赖输入。如果定义已变更，控制台会显示差异并要求显式确认。
- 重放可仅选择失败、超时或缺失的广播/分片目标，仍复用 execution + Outbox 的幂等与可靠投递边界。

## 兼容性与接入边界

本版本保持 Plugin API level、Executor Protocol 和核心数据库 schema 兼容范围不变。Backfill 表通过可重复执行的增量 feature migration 创建。在多 API 节点部署中，每个节点都可以运行 worker，实际推进权由数据库租约和 fencing 决定，无需单独部署补数服务。
