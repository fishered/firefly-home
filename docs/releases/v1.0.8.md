# Firefly v1.0.8

发布日期：2026-08-25

`v1.0.8` 聚焦发布一致性、验证闭环和生产可观测性基础。它不改变已发布的 v1.0.7 tag，而是在合并后的新提交上统一版本默认值并建立发布前检查。

::: tip 正式发布
`v1.0.8` 源码 tag 和 GitHub Release 已发布；Maven Central 构件由 tag 驱动的发布 Action 推送。可查看 [源码 tag](https://github.com/fishered/Firefly/tree/v1.0.8)、[GitHub Release](https://github.com/fishered/Firefly/releases/tag/v1.0.8) 和 [Central Portal](https://central.sonatype.com/artifact/io.github.fishered/firefly-spring-boot-starter/1.0.8)。
:::

## 发布一致性

- Gradle 项目版本、`.env.example`、Dockerfile、Docker Compose、README 和部署示例统一为 `1.0.8`。
- JAR manifest 注入 `Implementation-Version`，插件在生产环境可以获得真实构建版本。
- `verifyReleaseVersion` 检查容器默认值和文档示例，避免旧镜像版本再次漂移。

## 兼容性验证

- CI 的 Java job 执行 `check` 和 `verifyPluginCompatibilityMatrix`，而不只运行单元测试。
- Maven Central 发布前执行相同的兼容性与版本验证。
- 兼容矩阵增加 v1.0.8 节点，并检查 tracing 插件的 `runtimeCompatibility()` 是否与 JSON 契约一致。

## Trace 边界

- OpenTelemetry `service.version` 优先使用宿主构建版本。
- 持久化和传输 carrier 只允许 `traceparent`、`tracestate`、`baggage`。
- 单值最多 4096 字符、总长度最多 8192 字符，防止敏感字段和异常大 payload 进入 Outbox snapshot。
- 增加 carrier 过滤/大小限制和服务版本 resource 的测试覆盖。

## 兼容性

- 无数据库 Schema 迁移。
- 无 Netty/Executor 协议变更。
- 无 Admin API 请求或响应格式变更。
- v1.0.7 可直接滚动升级到 v1.0.8。

## 验证

- 插件兼容矩阵校验通过。
- scheduler-core、tracing-opentelemetry、JDBC 和 Netty 目标测试通过。
- PR 合并后的 GitHub Actions 运行完整 CI；发布 Action 使用 `v1.0.8` tag 执行 Maven Central 发布。
