# Firefly v1.1.4

发布日期：2026-09-24

v1.1.4 是一次可恢复执行正确性加固版本。它不扩大 1.1.3 的产品边界，而是让数据就绪、事件聚合、补数、重放、资源准入和发布流程在超时、并发、重启及多节点场景下保持可预测。

## 本次交付

- 数据就绪条件改为有界异步评估。Scheduler tick 只读取缓存结果；慢条件、异常和未知条件均有明确的超时与 fail-closed 行为。
- Backfill 固定启动时的任务定义快照，每个 fire time 使用独立且长度受限的 execution root；Replay 使用独立 root，并把选定的失败实例或分片精确传递到 Gateway。
- 事件聚合新增租约式 `claim` / `release` / `complete` 协议和 JDBC 行锁存储。H2、MySQL、PostgreSQL 的增量迁移现在可以跨节点恢复 aggregation window。
- SLA 区分预测风险与已经发生的违约；资源选择按 executor 隔离，支持轮询、随机、一致性哈希和原子预留回退；业务结果校验只接受完整 SHA-256 摘要。
- 派生 execution ID 统一限制长度并使用 SHA-256 后缀，避免长 job、实例、aggregation key 或幂等键超出数据库列宽。
- Maven Central 发布复用完整 CI，发布前强制通过 Java 与插件、Admin UI 与 Playwright、真实数据库以及全部 Spring Boot 兼容矩阵。

## 兼容性与接入边界

本版本保持 Plugin API level、Executor Protocol 和核心数据库 schema 兼容范围不变；事件聚合表通过可重复执行的 feature migration 增量创建。Backfill 游标、Replay 管理接口和资源快照仍未接入 Admin HTTP/UI；`BusinessResultSummary` 与 `SchedulingInputRevision` 仍是公共协议模型，不改变现有 `Handler` 的返回契约。
