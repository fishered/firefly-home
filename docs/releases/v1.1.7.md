# Firefly v1.1.7

发布日期：2026-10-18

v1.1.7 完成生产运营闭环，让 1.1.6 已具备的高可用、资源感知和补数能力能够在十万级管理数据、外部事件重试及真实故障环境中安全运行和恢复。

## 本次交付

- execution、Backfill、审计、任务历史和 Dead Outbox 全部改为服务端 keyset 游标分页，支持条件过滤、稳定的时间与唯一 ID 排序及覆盖索引。Admin UI 的五类查询均接入真实翻页，十万行门禁验证查询保持有界。
- 外部事件 HTTP 入口强制 HMAC-SHA256、时间戳、nonce、防重放和独立请求体上限；JDBC 运行时默认使用持久化 inbox/nonce，重启后仍能识别重复事件。
- 失败事件保存目标任务和失败原因，支持分页查询、确认和复用原 execution root 的幂等重放；运维操作进入审计日志，并输出接收、重复、失败、重放和安全拒绝指标。
- 生产门禁覆盖网络延迟与分区、Gateway 通信恢复、TLS/mTLS 身份和信任热轮换、Outbox claim fencing、旧 shard token 及迟到终态写入；PostgreSQL 备份恢复脚本可在 CI 或预发复现。
- JDBC feature migration 的并发锁覆盖全部增量 schema 变更，PostgreSQL 标准初始化脚本同步包含 v13-v19 feature schema。

## 兼容性与升级

本版本保持插件 API level 1、Executor 协议 v1/v2、任务定义和数据库 schema 兼容版本 12 不变，支持从 1.1.6 原地滚动升级。新索引和事件 inbox 等表通过可重复执行的增量 feature migration 自动创建。

升级后应验证签名事件只创建一个 root execution、重复 nonce 被拒绝、失败事件可以查询和幂等重放，并检查管理端分页及 Prometheus trigger 指标。完整步骤见源码仓库的 [1.1.7 升级说明](https://github.com/fishered/Firefly/blob/v1.1.7/docs/upgrade-v1.1.7.md)。
