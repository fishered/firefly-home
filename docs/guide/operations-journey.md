# 首次接入与运维诊断

管理台的工作路径是“接入 → 创建 → 运行 → 诊断 → 调整”。此页面描述 v1.2.2 管理台改造的使用方式；安装依赖仍以 [快速开始](./quick-start.md) 为准。

## 接入第一个远程任务

1. 启动 Firefly Server 和 Admin UI，登录后进入 **总览 → 首次接入**。
2. 逐项检查数据库与 API、Gateway、认证、Integration Key、Executor、Handler 和首个成功任务。待处理项会给出检查入口。
3. 在 **账号与安全**生成 Integration Key，并立即保存。服务端只保留摘要，关闭弹窗后不能再次读取明文。
4. 复制首次接入页的 Spring Boot YAML，将执行器名、Gateway 地址和 Admin API 地址改成实际部署值，通过 `FIREFLY_INTEGRATION_KEY` 环境变量提供密钥。
5. 启动业务服务，在 **任务管理**使用四步向导确认目标、调度、资源与预览。立即触发任务后，从 **执行记录**确认成功。

## 处理异常

进入 **运行 → 待处理中心**。每项显示原因、影响、建议操作和关联对象。点击“处理”跳转到执行记录、执行器、补数、租户或节点等对应页面。

执行详情读取 `GET /api/executions/{id}/timeline`，按触发、配额准入、Outbox、Gateway、ACK、执行和重试/重放排列。时间线中的“暂无观测数据”表示该阶段尚无持久化事件，不能把它解释成成功或失败。目标执行表仍保留实例、Gateway、ACK 和错误明细。

编辑任务与租户配额时先预览。表单修改后需要重新预览；请求失败时输入保留。两者都由服务端 `expectedVersion` 原子校验保护，冲突返回 409。任务版本也会随调度游标推进；活跃任务偶尔需要重新打开并预览，当前输入会保留供核对。

待处理中心聚合当前分页数据，不代表集群全历史告警总量。对于完整审计请使用 Admin API 或对应分页页面。
