# Firefly v1.1.4

Release date: September 24, 2026

v1.1.4 is a correctness hardening release for recoverable execution. It keeps the product boundary introduced in 1.1.3 while making readiness, event aggregation, backfill, replay, resource admission, and publication predictable under timeouts, concurrency, restarts, and multi-node operation.

## Delivered

- Data-readiness checks now run through a bounded asynchronous evaluator. Scheduler ticks consume cached results, while slow, failed, and unknown conditions have explicit timeout and fail-closed behavior.
- Backfill captures a job-definition snapshot at startup and gives every fire time an independent, bounded execution root. Replay uses its own root and routes selected failed instances or shards precisely through the Gateway.
- Event aggregation now provides leased `claim` / `release` / `complete` semantics and a JDBC row-locking store. Additive migrations for H2, MySQL, and PostgreSQL make aggregation windows recoverable across nodes.
- SLA evaluation distinguishes predicted risk from an observed breach. Resource selection is isolated by executor and supports round-robin, random, consistent-hash, and atomic reservation fallback. Business-result validation requires a complete SHA-256 digest.
- Derived execution IDs use a common length bound and SHA-256 suffix, preventing long job names, instance IDs, aggregation keys, or idempotency keys from exceeding JDBC columns.
- Maven Central publication now reuses the complete CI suite, requiring Java and plugin tests, Admin UI and Playwright checks, real databases, and the full Spring Boot compatibility matrix before upload.

## Compatibility and integration boundary

This release preserves the Plugin API level, Executor Protocol range, and core database schema compatibility range. Event-aggregation tables are created by repeatable additive feature migrations. Backfill cursors, replay management endpoints, and resource snapshots are still not exposed through Admin HTTP/UI. `BusinessResultSummary` and `SchedulingInputRevision` remain public protocol models and do not change the existing `Handler` return contract.
