# Firefly v1.2.1

Release date: November 7, 2026

v1.2.1 completes the quota-preview and capacity-planning workflow on top of the 1.2.0 multi-tenant governance foundation. Operators can inspect current usage, historical peaks, saturation, and rejection evidence before changing a quota, adopt deterministic recommendations per resource, and apply the result through the existing version CAS.

## Delivered

- `POST /api/tenants/{tenantId}/quota-preview` reads policy, usage, and capacity samples without creating reservations or changing Outbox, audit, or tenant-version state.
- Concurrency, CPU, memory, backlog, and trigger rate each expose current, average, peak, saturation, rejections, recommendation, quality, and stable reason codes.
- Recommendations use `ceil(max(current, peak) * (1 + headroom))`. Low coverage, quota-censored data, or mixed policy/runtime versions never produce a false-precision downsize recommendation.
- The Admin UI supports preview, per-field adoption, critical-risk confirmation, and apply with the same `expectedVersion`. Concurrent changes return `409 tenant_version_conflict`.
- The fleet-wide report is risk ordered and supports bounded JSON/CSV export. Pages are capped at 500 tenants; exports are capped at 1,000 tenants and 2 MiB.
- Additive v21 feature migrations create capacity samples and flush deduplication. The admission hot path only updates a bounded memory buffer, so storage failure or backpressure cannot block admission, dispatch, or terminal-state transactions.

## Compatibility and upgrade

The release preserves Executor v1/v2, Plugin API level 1, job definitions, the fair queue, and core database schema version 12. 1.2.0 and 1.2.1 nodes can coexist during a rolling upgrade. Mixed-version windows are labeled `MIXED_VERSION` and do not produce unreliable downsize recommendations.

Back up the database and install the v21 migration for the selected dialect before upgrading. To roll back to 1.2.0, stop the sampler; the additive tables may remain. See [Quota and Capacity Planning](../features/capacity-planning.md) for the complete operating model.
