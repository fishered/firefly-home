# Firefly v1.2.2

Release date: November 23, 2026

This release organizes the Admin workflow around setup → create → run → diagnose → adjust, so operators can follow a complete task path.

## Delivered

- The setup guide checks API and database, Gateway, authentication, Integration Key, online Executors, registered Handlers, and a first successful job. It generates Spring Boot configuration with an environment variable for the key.
- Job creation now has four steps: execution target, schedule, resources, and review. Advanced policies are collapsed by default.
- The action center brings together failed executions, offline Executors, dead dispatches, failed events, backfill failures, tenant capacity risks, and node failures from currently loaded data.
- Execution details read the existing timeline API and organize trigger, quota admission, Outbox, Gateway, ACK, execution, and retry/replay with a diagnosis and suggested action.
- Navigation is grouped into five areas. Global search, URL-backed filters, status labels, and resource units improve recovery and comprehension. Job and tenant changes require a preview; job updates use atomic `expectedVersion` checks and preserve input after a conflict.

## Compatibility and limits

There is no new scheduling protocol or database migration. The existing `firefly_job.version` also advances with the scheduling cursor, so an active job may need a new preview. The action center covers current pages, not complete alert history. Quota admission and Outbox do not yet persist precise events; the timeline marks those stages as unobserved.

## Verification

Java and Admin UI regression tests, 10 browser tests, production-readiness checks, and the Maven compatibility matrix for Spring Boot 3.3.5, 3.4.12, 3.5.8, and 4.0.0 passed. The 10-minute setup, 2-minute job creation, and 60-second diagnosis goals still require timed testing in a fresh deployment; automated tests do not prove those durations.
