# Firefly v1.1.7

Release date: October 18, 2026

v1.1.7 completes the production operations loop so the high-availability, resource-aware, and backfill capabilities delivered in 1.1.6 can be operated safely with hundred-thousand-row datasets, retried external events, and real failure conditions.

## Delivered

- Executions, backfills, audit records, job history, and Dead Outbox entries now use server-side keyset cursor pagination with filters, stable timestamp-plus-ID ordering, and covering indexes. All five Admin UI views use real server paging, and the 100,000-row gate verifies bounded queries.
- The external event HTTP endpoint now requires HMAC-SHA256, timestamps, nonces, replay protection, and an independent request-body limit. JDBC runtimes use a durable inbox and nonce store by default, preserving duplicate detection across restarts.
- Failed events retain the target job and failure reason and support paged lookup, acknowledgement, and idempotent replay against the original execution root. Operator actions are audited, with metrics for accepted, duplicate, failed, replayed, and security-rejected requests.
- Production gates cover network latency and partitions, Gateway communication recovery, hot TLS/mTLS identity and trust rotation, Outbox claim fencing, stale shard tokens, and late terminal writes. A PostgreSQL backup-and-restore script is reproducible in CI or staging.
- The JDBC feature-migration lock now protects every additive schema change, and the canonical PostgreSQL initialization script includes feature schemas v13 through v19.

## Compatibility and upgrade

This release preserves Plugin API level 1, Executor Protocol v1/v2, job definitions, and database schema compatibility version 12. It supports an in-place rolling upgrade from 1.1.6; new indexes and event-inbox tables are created by repeatable additive feature migrations.

After upgrading, verify that a signed event creates exactly one root execution, a repeated nonce is rejected, failed events can be inspected and replayed idempotently, and Admin pagination plus Prometheus trigger metrics are healthy. See the source repository's [1.1.7 upgrade guide](https://github.com/fishered/Firefly/blob/v1.1.7/docs/upgrade-v1.1.7.md) for the complete procedure.
